# Whereabouts v0.4 "Detect" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Warn at once about impostor programs (same name as a known, established, signed program, but not signed by the same publisher), and decide in the lab whether beaconing ships on.

**Architecture:** A new behaviour reason `Signal::Impostor` (high), raised by the Learner when it creates a profile for a new program path, by comparing with saved profiles. `AppFacts` gains `signature_checked` so "couldn't check" is never "unsigned". The lab's renamed-program test is scored by the new reason; long lab sessions decide beaconing.

**Tech Stack:** Rust 2024 workspace (store, detect, service, lab-replay), Svelte 5 + TypeScript (node:test), Python lab (uv, pytest), GitHub Actions `lab.yml`.

**Spec:** `docs/superpowers/specs/2026-11-27-v0.4-detect-design.md`

## Global Constraints

- Impostor rule: another saved profile whose **program file name** (from its path, case-insensitive) equals the new program's and whose **path differs** (case-insensitive), that has a stored `last_publisher`, is **established** (`!Profile::is_learning(now)`), and the new program is unsigned, invalid, or signed by a different publisher (case-insensitive). Skip when `signature_checked` is false.
- `Signal::Impostor`: store spelling `impostor`, severity **High**, toggle **on** by default, raised even while the new program is learning; `value` = the known program's path; lasting allow key `behaviour|{new key}|impostor|{known path}`; no profile item kind.
- Beaconing goes on in `Toggles::default` only if the held-out lab run with it passes the release bar (≤ 1.0 medium+ false alarms per user-week and ≥ 50 % detection in ≥ 3 of 5 types); thresholds tuned on the development run only.
- `renamed_binary` counts as detected for the bar only by a reason `impostor`.
- No new stored data; PRIVACY.md unchanged.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; a CHANGELOG line under `## [Unreleased]` where users notice; clippy `-D warnings` and `cargo fmt --check` clean.

## Review Focus

1. **Two real installs from the same publisher** (Discord + Discord PTB; a per-user and a Program Files copy of one app) → no warning. Test: `same_publisher_elsewhere_is_not_an_impostor` (Task 2).
2. **A vendor's signed installer is known** (`setup.exe`, still learning) and another vendor's `setup.exe` appears → no warning. Test: `learning_namesake_is_not_compared` (Task 2).
3. **Signature couldn't be read** → no warning. Test: `unchecked_signature_is_never_an_impostor` (Task 2).
4. **Case differences** (`CHROME.EXE` vs `chrome.exe`; same path in another case) → names match case-insensitively; the same path in another case is not "a different folder". Test: `names_and_paths_compare_without_case` (Task 2).
5. **"This is fine" / Reset** → no repeat warning for that path after This is fine; Reset removes the allow. Test: `allowed_impostor_does_not_warn_again` (Task 2).
