## Whereabouts 0.4.0 — developer preview

*Detect.* Whereabouts now warns at once about a program posing as one you already use.

### The impostor warning

Malware often copies the name of a program you trust (for example, a fake `Discord.exe` in a download folder) so it blends in. In 0.3 such a copy counted as a brand-new program and was still learning, so it could not be caught.

Now, when a program has the same file name as one you have used for at least a week, but is in a different folder and **not signed by the same publisher** (unsigned, or signed by someone else), Whereabouts raises a **high** alert straight away: *"Same name as {the program you use}, but not signed by the same publisher. It may be pretending to be that program."*

- Only a program you have used for a week or more counts as the original, and the newer of the two is the one warned about.
- A signature Whereabouts could not check does not count.
- Each program is checked once a day. **Dismiss** means "remind me": it comes back the next day if the copy is still there. **This is fine** stops it for that pair of programs.

### Other changes

- **Dismiss all** on the Alerts screen marks every alert that needs a look as seen. They stay under *All*, and an alert comes back if the same thing happens again.
- **Browsers no longer get "random-looking name" warnings.** They reach ad and content-network names that only look random all day, and in the lab this caused most false alarms. Other apps still get them.
- **Beaconing detection (regular check-ins to one place) stays off.** Re-measured with 3-hour lab sessions, it still raised too many false alarms (a browser checking in with an ad network). When switched on, it now ignores Windows' own services checking in with Microsoft.

### How well does it work?

In the lab, with simulated users and fresh traffic that nothing was tuned on (run 46018775655), the result was **"Release bar: PASS (false alarms 0.188 ≤ 1.0; types at ≥ 50 %: 3 of 5)"**. It found swapped programs 100 % of the time, hidden uploads 75 % and random-looking domains 69 %. This is the run scored after two fixes to the lab's replay (it now passes each program's signature to the detector, and marks the lab's own test browser as a browser); with the detector unchanged, the first scoring of the same run gave 0.938, also a pass.

None of the simulated users in that run had the program the renamed copies posed as, so it could not test the impostor warning. On the development data it caught 26 of the 27 renamed copies of an app the user had used for a week, with no false alarm. **These are lab numbers on GitHub's datacenter computers, not real-world rates.** See [section 6.2 of the design spec](https://github.com/Razni-Ahamed/Whereabouts/blob/main/docs/design-spec.md).

### Install or update

1. Download `Whereabouts_0.4.0_x64-setup.exe` and `SHA256SUMS.txt`.
2. **Check the checksum.** This preview is not code-signed yet, so Windows SmartScreen may warn:
   `(Get-FileHash .\Whereabouts_0.4.0_x64-setup.exe -Algorithm SHA256).Hash`
3. Run it and approve the administrator prompt.

**Updating from 0.3.0:** run the installer. It stops the running service, replaces the programs and starts the service again. Your history, profiles, blocks, alerts and settings are kept.

Requirements: Windows 10 22H2 or Windows 11, 64-bit.

### Known limitations

- The installer is **not code-signed** yet.
- A renamed copy is caught only if the program it imitates has been used for a week and is signed. A copy of an unsigned program, or one seen before the real program, is not caught by this warning.
- A copy that keeps a real publisher's valid signature (a renamed genuine file) is not an impostor and is not warned about.
- Each connection's bytes are spread evenly over the hours it lasted, so "unusual hour" is rough.
- A swapped program file is watched for 24 hours in memory only: if it reaches only known places until Whereabouts restarts, it is not caught afterwards.
- The lab numbers above are simulated; real-world false-alarm rates may differ.
